# Record and I/O contract
ReadRecord owns UTF-8/ASCII-graphic identifier, ordered Vec of (key,value) annotations, original-case sequence bytes, optional decoded Phred u8 vector, zero-based u64 input ordinal. No hash traversal controls serialization.
Header grammar: ID followed by zero or more |KEY=VALUE fields. ID is nonempty ASCII graphic excluding '=' and delimiters. Keys are nonempty uppercase ASCII letters/digits/underscore. Values are nonempty ASCII graphic excluding '=' and '|'. Missing fields remain absent; duplicate keys, empty/malformed fields, whitespace, non-ASCII and unsupported keys are errors. Annotation order and comma-containing values are preserved without aggregation or interpretation. This strict subset is not a pRESTO header compatibility claim.
Sequence alphabet: upper/lower ACGTURYSWKMBDHVN plus gap '-' and '.', nonempty. FASTQ is four physical lines: @header, sequence, '+' optionally repeating exact header, qualities. Qualities are ASCII 33..126, decoded 0..93; lengths must match. Wrapped FASTQ is unsupported. FASTA supports multiline sequence and canonical single-line output, no blank lines. LF/CRLF and final unterminated lines accepted. Empty files contain zero records.
Input is buffered and magic-detected plain/gzip; concatenated gzip members supported. Invalid UTF-8, framing, symbols, truncated input, gzip corruption and I/O errors propagate. Lines and assembled FASTA sequences have a 16 MiB cap; storage is per record, not whole file. An over-limit line may consume one extra byte before failure. Ordinal and aggregate counter overflow are errors.
Writers validate records and preserve sequence, qualities and annotation order. FASTA refuses quality-bearing records to prevent loss. Normalization changes wrapping/newlines/plus-line representation only. Writers produce plain output; gzip output and stdin/stdout sequence streaming are deferred.
Normalization stages beside destination with create_new and .partial.PID suffix; flush+sync precede atomic hard_link publication without overwrite. Drop attempts stage cleanup. Failed parse/write cannot publish the destination. Crash residue is visibly partial; completion is indicated by the final file and successful command exit. Unsupported hard-link filesystems fail. Directory fsync/power-loss durability and guaranteed cleanup after process kill are not claimed.
CLI: validate/inspect FORMAT INPUT stream and report checked records/bases counts. normalize FORMAT INPUT OUTPUT writes a new destination. compare FORMAT LEFT RIGHT emits structural categories. --version/--help supported. Success 0, argument/parse/I/O/difference failure 2. Duplicate record IDs are valid I/O but comparison reports ambiguity.
